# Supercombo 양자화 열화 — 원인 분리와 구조적 저감 (2026-09-04)

`053837e`의 기본 모델(중심화 로짓 + 혼합 PTQ 173 + SQuant)을 기준으로 남은 양자화 열화의 원인을 분리하고,
런타임 비용 없이 줄일 수 있는 구조적 레버를 실제 K230에서 검증했다. 채택한 변경은 세 가지다:
GRU `Tanh`를 `2·Sigmoid(2x)−1`로 계산, 가중치 사전 양자화 + bias correction, 보정 데이터 173→300장.
순환 추론 1,320프레임(6 루트, 보정·선택에 쓰지 않은 세그먼트)에서 plan 후보 일치 87.5→94.5 %, 선택 경로 y MAE 15.6→11.3 cm(P95 63→44 cm),
비-logit 출력 MAE 0.093→0.062, 차선 좌표 MAE 0.218→0.158, 리커런트 state MAE 0.0184→0.0075. pose MAE는 0.041→0.047로 약간 나빠졌다. 추론 시간은 동일하다.

## 모델 식별

- 기준 kmodel: `3bc1c91da706f99245168a6e231d17609a5b1b8b23d7ad1aabb70b749293d8a9` (053837e 기본), 비교용 `6c86a4a` 모델 `168e6a15…`.
- 원본 ONNX SHA-256 `50c7fc8565ac69a4b9a0de122e961326820e78bf13659255a89d0ed04be030d5`, nncase 2.11.0 / nncase-kpu 2.11.0, K230.
- 모든 지표는 실제 보드(`sequence_runner` mode 3, 운영 스택 동작 중)에서 측정했다. 시뮬레이터와 보드 출력은 비트 동일(첫 프레임 6524값 전부 일치)을 확인해 단일 노드 프로브에는 시뮬레이터를 썼다.
- 최종 아티팩트: 아래 “최종 아티팩트” 절.

## 평가 데이터 (053837e의 검증 데이터와 독립)

- 6개 루트의 held-out 세그먼트(세그먼트 index % 3 == 1)에서 각 260프레임을 잘라 앞 40프레임은 FP32 워밍업 state로만 쓰고 220프레임을 평가:
  `day_0816`(60 km/h 주행), `day_0819b`(1280×704 옛 카메라 형상, 시내 20~35 km/h), `day_0830hw`(고속도로 54 km/h), `eve_0903`(저녁 시내), `night_0830a`(야간 40~50 km/h), `night_0901`(야간 정차, 평균 휘도 10).
- 독립 모드: 각 시퀀스 11프레임 간격 20장 = 120프레임에 FP32 state를 주입 → 변환 오차만. 순환 모드: 1,320프레임, 각 모델이 자기 state를 되먹임.
- 입력은 런타임과 같은 C++ fixed12 워프(`ModelInputTransform`)로 녹화 HEVC→NV12→YUV6 변환. desire는 ControlState rising edge로 복원.
- 보정 풀: 10개 루트 287장(정차 36 %, 야간 30 %), FP32 20프레임 워밍업 state. 이 중 127장을 mixed173에 더해 300장 세트로 썼다(`models/ptq/supercombo_calib_k230_127.npz`).

## 원인 분리 (독립 모드, 기본 모델 구성)

FP32 ONNX에 각 양자화 단계를 에뮬레이션해 보드 실측과 비교했다.

| 오차 원천 | 비-logit MAE | 근거 |
|---|---:|---|
| 가중치 uint8 채널별 반올림 | 0.013 | 스킴 by_channel 범위로 가짜 양자화 |
| + 활성 int16 양자화(NoClip 범위, 전 텐서) | +0.001 | |
| + FP16 반올림(전 텐서) | +0.0001 | |
| 보드 실측 | 0.051 | 잔여 0.035는 KPU 커널 수치 |

텐서별(per-tensor) 가중치 에뮬레이션은 0.37로 실측의 7배 → nncase 기본은 채널별 양자화다. KPU 최종 출력은 FP16 격자(|v|>128에서 0.125 간격 100 %).

### KPU 활성 함수 프로브 (단일 노드 모델, int16 PTQ, 시뮬레이터)

| 함수 | 평균 절대오차 | 최대 절대오차 | 특징 |
|---|---:|---:|---|
| `Elu` (native) | 0.0020 | 0.031 | x∈[−2,0)에서 평균 +0.012 편향, 입력 범위와 무관 |
| `Relu(x)+Exp(−Relu(−x))−1` | 0.0004 | 0.0020 | `Exp` 오차 0. 79개 전부 적용 시 4.6배 느림 |
| `Tanh` (native) | 0.0108 | 0.038 | 0쪽으로 눌림(|x|<2에서 ±0.024 편향) |
| `2·Sigmoid(2x)−1` | 0.0016 | 0.013 | |
| `Sigmoid` | 0.0008 | 0.0064 | 편향 없음 |
| `Relu` | 0.0003 | 0.0020 | FP16 출력 반올림 수준 |

GRU 후보 상태가 `Tanh` 출력이므로 그 편향이 매 프레임 state를 오염시키고 순환 추론에서 증폭된다. 이것이 잔여 오차의 최대 단일 원인이었다.

## 기각된 레버 (실측)

- `UseAdaRound`: kmodel SHA가 미세조정 없음과 동일(무효). `use_mse_quant_w`도 무효(053837e 보고).
- 부분 int16 가중치(스킴 `DataType=i16`): 컴파일은 되지만 출력 붕괴(plan 일치 6 %, 비-logit MAE 2.0), 15~40배 느림, 정상 종료 후에도 CMA 미반환. 작은 헤드 5개만 바꾸면 변화 없음.
- 채널별 범위 스킴 재주입(`use_mix_quant` 없이): 미세조정 없음과 동등. `use_mix_quant=True`와 함께 주면 nncase 크래시.
- ELU/ReLU 앞 음수 범위 절단: ELU 오차가 범위와 무관하므로 무의미(중단).
- Cross-layer equalization(ReLU로 이어진 Gemm 쌍 20개): 에뮬레이션에서 이득 없음.
- ELU 79개 전부 분해: 독립모드 비-logit MAE 0.049→0.026, 그러나 프레임당 738 ms(u8 160 ms, 동일 조건) → 실시간 불가.
- bias correction 표본 48→128장: 차이 없음. 보정 460장 컴파일: colima 10 GiB에서 OOM.
- KPU ELU 편향 g(x)를 ReLU 기저로 근사해 bias correction 계산에 포함(`kbc.py`): 보드에서 출력 붕괴(plan 일치 25 %). 근사가 실제 커널 오차와 맞지 않아 보정이 오히려 큰 편향을 주입했다.

## 최종 아티팩트

`scripts/build_supercombo_model.sh`로 재생성한 `models/supercombo.kmodel`:

- SHA-256 `2e9759c73001e587aebdc66d7473479a9752ba9bbb7d67a3744347675b7ade99` (27.27 MiB, 컴파일 398 s).
- 구성: 053837e 재작성 + `--tanh-via-sigmoid` → `prequant_bias_correct.py`(300장 세트 중 48장, 스킴 격자 204/204 레이어) → uint8 입력 → NoClip int16/uint8, 미세조정 없음, 300장.
- 위 표의 “최종(빌드 스크립트)” 열이 이 파일의 보드 실측이다(재부팅 직후 측정). 후보 `Tanh교체+BC+보정300`(BC 128장, 다른 표본)과 수치가 거의 같아 BC 표본 선택에 민감하지 않다.
- 보드 운영 모델(`/root/supercombo_k230/model/supercombo.kmodel`, md5 `697745a1…`)은 교체하지 않았다.

주의: `sequence_runner`는 실행마다 CMA 약 90 MB를 반환하지 않는다(7회 실행 뒤 CmaFree 875→218 MB, modeld 19.8→13.9 fps). 평가 뒤에는 보드를 재부팅했다.
