# K230 supercombo model

The deployed model is openpilot **v0.9.4** `supercombo`, compiled for the K230
KPU. `scripts/build_supercombo_model.sh` rebuilds it end to end.

## Contents

- `supercombo.kmodel`
  - the deployed model: uint8 image inputs, int16 activations, uint8 weights.
- `ptq/supercombo_calib.npz`
  - 60 PTQ samples captured from recorded K7 drives (city night, highway dawn,
    highway night) with the model's own temporal inputs, built by
    `tools/model/make_calibration.py`.
- `onnx/` (untracked)
  - intermediate `supercombo_base.onnx` (fp32) and `supercombo_uint8.onnx`
    regenerated by the build script from the pinned upstream release.
- `manifest.sha256`
  - SHA-256 manifest for the tracked files.

## Contract

```text
0 input_imgs          [1, 12, 128, 256]  uint8
1 big_input_imgs      [1, 12, 128, 256]  uint8
2 desire              [1, 100, 8]        20 Hz rising-edge pulses, newest last
3 traffic_convention  [1, 2]
4 nav_features        [1, 256]           unused, zero
5 features_buffer     [1, 99, 128]       previous outputs, newest last
-> outputs            [1, 6120]
```

Both image towers are active: the runtime samples one `1280x720` NV12 frame
through two calibrated virtual cameras (`medmodel` fl=910 and `sbigmodel`
fl=455) and keeps independent two-frame histories, writing each warped frame
straight into its nncase tensor. The 128-float feature vector at offset 5990
is fed back through `features_buffer`; there is no GRU state.

`k230_modeld` verifies this contract at load and refuses any other kmodel, so
a mismatched model fails loudly instead of being misparsed.

## Verification

Board measurements for this build (K230, pipeline stopped):

| check | result |
| --- | --- |
| NPU time | 28.6 ms/frame, inside the 50 ms 20 Hz budget |
| uint8 image retype | bit-identical to the fp32 graph (max diff 0.0) |
| int16 PTQ vs host fp32, 100 real frames | plan lateral 0.016 m mean / 0.047 m max at 2 s, lanes 0.025 m mean |
| runtime end to end (warp + temporal inputs + kmodel) vs host fp32 | plan lateral 0.024 m mean / 0.062 m max at 2 s, lanes 0.048 m mean |
| feature buffer liveness | frame-to-frame correlation 0.77 |

The end-to-end row is the one that covers the on-device warp and the temporal
plumbing; `docs/diagnostics.md` documents how to reproduce it after any model
change.

Quality against the recorded drives (held-out routes, error against the path the
car actually drove, reconstructed from CAN speed and steering): plan lateral
error 0.51 m at 2 s. This is the metric that selected this model; it is
lineage-independent, so any candidate model can be scored the same way with
`tools/model/make_replay.py` and compared against this number.
